# FGO AI v1.1.1

## 连续人工请求计数

- 仅统计连续的新 AI 人工请求；中间出现正常决策、真实请求失败或本地流程恢复进展，立即清零，不再按模式累计一整次运行中的历史次数。
- 正常出牌会清掉此前的助战人工计数；连续人工请求仍按现有配置阈值暂停。冷却跳过不产生新回复，同一回复不会被旧调度分支重复计票。

## 助战与指令卡提示词

- 配置中的已知助战仅供参考，不是白名单；可根据当前截图评估未登记的可见从者。OCR 缺失身份、宝具等级或类型不等于不合格，未知信息仍须如实标记。
- NP 等级与类型偏好不再被误读为硬限制；`refresh_allowed=false` 只禁止刷新，不表示需要人工。当前页无合适行时返回 `continue_support_scan`，继续现有本地筛选、翻页与等级递降。
- 强化场次 `X/Y` 与绝对回合数的区别，修正指令卡 JSON 示例格式，并提醒输出独立视觉读数。
- 完整版与精简版提示词同步修复；每次出牌必须包含场次和绝对回合观察字段，读不清时明确报告未知。

## 自由关卡与通用恢复

- 整个自由关卡模式优先自身的地图、详情和导航处理；无法识别或画面持续未推进时，通用模板匹配和 unknown AI 仍可接管。
- 移除 loot_next 后结算监视的无条件等待，保留已确认地图、详情页、加载及战斗的正常分流。画面或阶段推进后恢复本地优先，不按动作总数停止任务。
- 自由关卡需要 AI 帮助时先尝试允许的通用模板；仍排除主线地图推进按钮，不放宽坐标和资源保护。

## 发布包

- Windows CPU/CUDA 双包统一为 `1.1.1`，复用已有 Nuitka/SCons 与编译器缓存，重新编译包含修复的程序。
- `--self-test` 增加实际编译代码的决策回归检查：正常出牌清零助战人工次数、连续人工阈值、助战继续扫描及自由关卡停滞恢复契约。
- 正常运行无需安装 Python。CUDA 要求与自检见 [GPU 配置](GPU_SETUP.md)，自由关卡配置见 [自由关卡说明](FREE_QUEST.md)。升级请先关闭旧程序，完整解压到新目录。

## 测试体验提醒

本项目仅供测试体验与技术交流，运行期间需要人工看护。误识别、误操作或异常循环可能消耗游戏道具、API 付费额度等资源；发现异常或无法继续看护时请停止自动化。
