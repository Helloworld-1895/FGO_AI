# AI 决策配置、低价选择与 Token 消耗

## 角色

AI 决策层负责在截图和结构化事实基础上选择助战、技能、宝具、目标、指令卡和未知画面动作；ADB、OpenCV、OCR 和本地动作守卫负责采集、定位、白名单校验与执行。模型只能返回受限符号动作，不能直接提交任意坐标或绕过危险动作拦截。

## 选择服务

- **本地优先**：安装 Ollama，使用支持视觉输入的本地模型。默认示例是 Qwen3-VL 2B；需要自行评估显存、内存、速度和模型许可证。
- **低价云端**：选择兼容 OpenAI Chat Completions 的服务商，比较输入、缓存输入、输出单价、图片 token 计费、速率限制、数据保留和地区可用性。不要因为“免费”或“低价”而把账号截图发送到不可信服务。
- **大模型**：可用于复杂未知画面或策略复核，但成本和延迟通常更高。先用本地规则和低价模型验证，再逐步提高模型能力。

项目不会推荐固定商业服务商，也不会替用户购买额度。价格、上下文限制和模型行为会变化，应以服务商当前价格页为准。

## 配置

1. 复制 secrets/tju_llm.example.json 到本机的 secrets/tju_llm.json，或在 GUI 的模型顾问页新建 profile。
2. 填写 endpoint、model、api_key。本地 127.0.0.1 接口可留空 key，远程接口必须使用自己的 key。
3. 先运行模型检查，再只开启一个 AI 模式。推荐先用观察/复核模式验证，再开启自动动作。
4. 密钥只保存在本机的 secrets 或用户配置中；绝不要提交、截图或写入 Issue。

## Token 消耗

实际用量以服务商返回的 usage 字段为准，GUI 会显示累计 total、input、cached input、output。下表是发布前的保守估算，不是账单承诺：

| 场景 | 单次请求常见输入 | 单次输出上限 | 说明 |
| --- | ---: | ---: | --- |
| 助战/未知画面判断 | 约 2,000-8,000 | 至少 32,768 | 可能含一张截图和规则上下文 |
| 指令卡/回合决策 | 约 3,000-12,000 | 至少 32,768 | 开启连续复核会重复发送上下文 |
| 后台笔记总结 | 约 5,000-20,000 | 32,768-65,536 | 仅在启用 notebook 总结时产生 |
| 联网研究/助手对话 | 取决于历史和检索结果 | 至少 32,768 | 结果越长消耗越高 |

代码向兼容接口声明的默认输出预算至少为 32,768 token；这只是最大预算，不代表每次一定消耗这么多。图片模型还可能按图片分辨率折算视觉 token。真实成本约等于：输入 token（扣除缓存折扣）乘输入单价，加上输出 token 乘输出单价，再加服务商的图片或请求费用。

为了控费：关闭不需要的 AI 模式，降低复核频率，使用本地 Ollama，启用服务商缓存，定期在 GUI 清零并记录 token 统计，给云端账户设置余额或速率上限。程序不会替你设置服务商账单上限。

## 故障与降级

接口不可用、超时、超预算或返回非法动作时，程序应使用本地规则、暂停或等待人工处理。不要为了节省 token 而关闭动作守卫，也不要把 API key 放进默认配置。
